the machine

Diagnose, treat, retrain, measure. Repeat until the rule says stop.

No human picks the next move. The agent reads its own training curves, chooses a treatment from a library of cited method cards, edits the model code, retrains, and keeps only what measures above an ε = 0.002 bar. A convergence rule, not a person, ends the run.

how it worked

The four stages, in depth.

You just watched six iterations. Here is exactly what happened inside each stage of every one of them.

01 · DIAGNOSE

Every trained node logs a learning curve: training loss and validation score at every epoch. The agent reads that curve the way an engineer would. Validation peaking early and then sliding while training loss keeps falling means overfitting. Both still improving at the last epoch means undertraining. A flat curve on a changed model means the idea did nothing. And because the run calibrates baseline seed noise first (3 seeds, σ ≈ 0.0001), the agent can tell a real effect from a lucky seed by reading the gap in sigmas. A telemetry gate keeps it honest: a diagnosis may only cite a curve that was actually recorded, and every diagnosis is written verbatim into the journal, so wrong calls stay visible. The one you just saw replayed, "validation peaks at epoch 8", is what steered the whole run.

02 · TREAT

The diagnosis selects from a library of 42 method cards, each a real technique from the ranking literature written down with its mechanism, when it applies, and what it has measured on this dataset so far. Overfitting points at regularization cards; a plateau points at ensembling or a family switch. The menu has two tiers, proven treatments versus evidence-ranked opportunities, and a strategy layer keeps the run phase-appropriate: establish a strong base first, exploit what measured, close with a cross-family ensemble.

03 · RETRAIN

The agent then writes a complete training script implementing the chosen treatment, against a frozen contract: read the prepared splits, train, emit validation predictions plus the per-epoch history the next diagnosis will need. A 360-second smoke test catches crashes before the full train. The hidden test window is never mounted into the workspace, so leakage is impossible by construction rather than by instruction. If a script crashes, a fixer model gets one repair attempt; an unrecoverable crash is logged VOID and the loop moves on.

04 · MEASURE

The official evaluator scores validation GAUC and nDCG@5 per user; the primary metric is their mean. A change is kept only if its gain clears an acceptance floor, and borderline gains must repeat on a second seed (a z-test against the calibrated noise). Convergence is the competition rule: three consecutive iterations within ε = 0.002 ends the run, hard cap 50. The run you just scrolled through ended exactly that way, with no human in the decision.

Structural leakage guard

The rule "never touch the hidden test set" is enforced by architecture, not by prompt. A data exporter builds the agent's workspace containing only the train and validation windows; the test file simply does not exist in any path the agent's scripts can read. On top of that, every generated script is screened before execution for test-window access patterns, and the two test-prediction tools (tools/predict_test*.py) carry explicit guards and are never callable by the agent. The hidden test set was scored exactly once, at final submission. When organizers acknowledged the test set ships with the data and asked teams not to use it, this structural guard became a differentiator: our compliance is checkable from the code, not attested.

Calibrated acceptance gate

Iteration zero trains the official baseline on three seeds and measures the noise floor: σ ≈ 0.0001 on validation primary. Every later delta is read in those units. A candidate is accepted outright only above a floor; borderline gains (the grey zone, floor 0.0005) must repeat on a fresh seed and pass a z-test against the calibrated noise before they count. We measured why this matters: the official ε = 0.002 convergence rule silently kills honest +0.0004 steps from a strong base, so a run that chases every twinkle converges early on noise, and a run with no floor accepts phantoms. The gate is versioned (floor-v2) and its history is in the repo, including the runs the earlier version handled worse.

The method-card library: 42 techniques, cited and measured

The agent's knowledge is not a prompt, it is a curated library compiled from the ranking literature (research/ surveys) and this campaign's own ledger. Each card names the mechanism, when it applies, its citation, and what it has measured on this exact dataset, updated as runs conclude. Cards move through honest states: measured-win, measured-dead (may not be re-selected in the same form), untried, parent-conditional. Two tiers separate proven treatments from evidence-ranked opportunities, and a strategy layer matches cards to the run phase. Telemetry-gated diagnosis, and the bug that taught us why

Every node script must emit its per-epoch history: train loss, validation GAUC, nDCG@5, learning rate. The diagnosis stage may only assert curve shapes that exist in that record; a proposal reasoning from an unrecorded curve is rejected as insufficient telemetry, and the run says so in its journal. We learned this the expensive way: mid-campaign we found two stale knowledge channels (an outdated directive and 17 stale card statuses) had been silently mis-steering selection for a day of runs. We purged them, rebuilt the channel so knowledge is loaded once at launch, and disclosed the two runs the earlier wrong doctrine had discarded rather than deleting them. Accurate memory turned out to be as important to autonomous research as model quality.

Typed ensemble plans: the agent plans, the harness executes

The campaign's strongest measured finding: cross-family blends beat same-family seed ensembles by an order of magnitude (+0.0013 vs +0.0003, with team evidence probes reaching 0.6058-0.6065). The farm-close capability turns that into a first-class move. The agent emits a typed, schema-validated JSON plan: which model families, which configs and seeds, which blend rule. A deterministic assembler then runs the three phases: parallel probe-fidelity fits of every family, exhaustive enumeration of every declared blend over the probe score vectors (cheap: rank averages of saved arrays), full training of only the complementary families, and a full-fidelity re-verification of the winning combination before anything is emitted. There is no LLM call inside the measurement path, an anchor rule guarantees a strong singleton fallback, and a legitimate "the incumbent won" is recorded as such rather than punished as a degenerate ensemble.

Decision benches: testing judgment like code

How do you regression-test an agent's judgment? We froze real run states (curves, menu, history) whose right next move we knew from measurement, and replay the brain against them after every harness change. The full-knowledge selector bench runs 8/8; the clean-mode strategy bench went 4/10 to 10/10 through methodology fixes alone, under a standing constitution: a bench fix may only be an evidence correction or a general principle, never a canned answer to a specific state. A third tool replays historical decision points over cached artifacts; it scores 0.60599, which we report as an optimistic cached-artifact counterfactual, not a result, a distinction an external review pushed us to sharpen and that we adopted across every claim on this page.
